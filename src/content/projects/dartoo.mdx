import N from '../../components/note/N.astro';

The ingestion pipeline looked healthy. Every request returned 200, every worker
reported success, and the disclosure table filled up on schedule. What it did not
do was publish the events that the rest of the system was waiting
for.<N id="dartoo-publisher-gap" />

The failure had no log line. When RabbitMQ came up after the disclosure service,
`EventPublisher` set `self.enabled = False` and never reset it, so once the broker
recovered the publisher stayed switched off and discarded every event in silence.
Success responses were telling the truth about persistence and nothing about
delivery. Reconciling the two counts was the only way to see it.

The fix was a lazy reconnect — keep the publisher enabled after startup failures
and reconnect on first publish — plus exponential backoff, a connection guard, and
a warning log with the receipt number so a discarded event can never again be
invisible.<N id="dartoo-e2e-parity" />

A separate assumption failed the same way. A retry counter had written off a batch
of `NOT_READY` responses as permanent, so I re-fetched four of them a week
later.<N id="dartoo-not-ready-experiment" /> All four returned normally. The status
code was mixed, not terminal, so the policy became a three-stage backoff for the
transient case and DLX isolation for the genuinely permanent
one.<N id="dartoo-test-count" />
