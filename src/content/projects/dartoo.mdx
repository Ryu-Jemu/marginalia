Dartoo turns regulatory filings into searchable records, summaries and subscriber alerts. I implemented **ingestion, disclosure and notification**, improved summary integration, and connected the Java User service's internal notification APIs.<N id="dartoo-ownership" />

**Source data and contracts.** The producer detects ZIP, HTML and XML, resolves encoding candidates and rewrites text as UTF-8. It stores the document in MinIO and passes the receipt number, object path and file metadata to the disclosure worker.<N id="dartoo-normaliser" /> Summary tasks read that object; the updated disclosure emits events for notification processing.

**Readiness and retry policy.** The 2026-04-08 record describes four filings returning normally a week after permanent-failure classification.<N id="dartoo-not-ready-experiment" /> I replaced the fixed counter with Redis-backed retry times and document metadata, then processed due items between polling cycles.

**Stored rows and published events.** The 2026-08-13 measurement record reports 959 stored rows and 805 events, a difference of 154.<N id="dartoo-publisher-gap" /> After publisher reconnect changes, the recorded single fixture E2E run produced 3,948 rows and 3,948 events.<N id="dartoo-e2e-parity" />

**Delivery and output quality.** Notification combines event identity, ten-step orchestration and a seven-day-TTL DLQ.<N id="dartoo-notification-scope" /> I aligned its structured payload with Java User APIs, and added summary JSON validation, safe fallback text and a Redis Lua counter.<N id="dartoo-lua-scope" /> A CLI on develop checks six external dependency types without sending a push.

**Verification record.** The 2026-08-13 local audit counted 319 def test_ function definitions across ingestion, notification and disclosure. This is a definition count, not a test-pass result.<N id="dartoo-test-count" />
