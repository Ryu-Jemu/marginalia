Google ID token verification, an upsert into users and social accounts, and
access and refresh tokens issued off the back of it — a spike to settle how
sign-in would work before committing to it in a real service.

The reason it is on this page is a test that passed when it should not have. To
check that a tampered token is rejected, I changed the last character of the
signature and asserted rejection. It rejected. The test was still wrong:
base64url encodes the final characters with spare bits, so several distinct
characters decode to the same bytes, and I had produced a token that was not
actually modified. Tampering with a character in the middle made the test mean
what I had assumed it meant all along.
