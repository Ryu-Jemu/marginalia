import N from '../../components/note/N.astro';

The premise going in was that surveillance density explains crime. Install more
cameras where crime is high — the policy writes itself. The data does not
support it.

Five variables across Seoul's twenty-five districts explain about 84% of the
variation between them.<N id="crime-model" /> The two that carry it are
population and the density of entertainment venues. CCTV count is not
significant.<N id="crime-significant" /> Crime concentrates where people and
nightlife concentrate, which is a different policy conclusion from the one the
project set out to confirm.

Getting there took more care than the fit itself. Population, income and
streetlight counts move together across districts, so I checked variance
inflation before reading a single coefficient — an unstable fit produces signs
that are noise, and every conclusion drawn from them is decoration. With
twenty-five rows a single OLS fit is one draw, so I re-fit with cross-validated
Lasso and Ridge; the same variables survived with the same explanatory power.

The last step was mapping the residuals rather than the predictions. A
prediction map flatters the model. A residual map names the districts it gets
wrong, and those are clustered in a way that points at a floating-population
variable I could not get at district
level.<N id="crime-streetlight-gap" /> That gap is in the report, next to the
result.
