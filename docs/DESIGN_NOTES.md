# 레이아웃 개편 근거

최종 정리: 섹션명은 학력·경험·역량·기여·기술·구조처럼 한 단어로 축약.
학력과 연구실·조교 경험은 별도 항목으로 분리. 자격은 개별 테두리로 구분.
홈 기술 배지는 상단 공통 목록에 한 번만 노출하고 프로젝트별 반복 행은 제거.
기타 작업은 CareerRadar·StarIndex만 표시. 아래 기록은 각 개편 단계의 설계 근거임.

현재 화이트·그라파이트·블루와 Pretendard를 유지하면서, 발표 장표처럼 반복되던 홈의 정보 구조를 변경.
사용자 추가 요청에 따라 소개를 맨 먼저 배치. 기존 프로젝트 내용·기여 구분·한국어 라우팅 유지.

## 선택한 구성

좁은 단일 문서형과 넓은 프로젝트 목록형을 비교. 실제 앱 화면을 함께 살펴볼 수 있도록
1,120px의 프로젝트 목록형 선택. 특정 사이트의 디자인을 복제하지 않고 정보 구조만 참고.

1. 소개: 이름·분야·핵심 이력·연락. 상세 이력·AI 활용·SWOT은 native details.
2. 대표 작업: MAP/Dartoo만 실제 목업과 3개 불릿·최대 4개 기술.
3. 그 밖의 작업: AI·데이터 분석·연구·기타의 간결한 링크 목록.
4. 상세: 왼쪽 목차와 읽기용 본문. 모바일은 단일 열.
5. STAR: 첫 사례 기본 펼침, 나머지 사례 선택 탐색. 기존 앵커로 직접 접근 가능.

큰 홍보 제목, 중복 프로젝트 목차, 번호 역량, 홈의 반복 도식, 반복 외곽 카드를 제거.
시각화와 모션은 실제 맥락이 있는 상세 화면·흐름 설명·수동 화면 전환에서 유지.
접힌 소개/SWOT/STAR의 직접 링크는 필요한 details를 열어 도착 지점을 표시.
native summary는 최소 64px 높이. `DisclosureIndicator`의 40px 색상 표시 안에 +/−,
옆에 `펼치기`·`접기`를 함께 제공해 조작 위치와 현재 상태를 명확히 표시.

## 최종 시각 체계

사용자 예시 [Ben Scott](https://benscott.dev/)의 강한 명암, 제목 강조선, 프로젝트 구획을 조사.
전체 검정 배경이나 대형 표지를 추가하지 않고, 기존 소개 우선 구조에 다음 원칙으로 적용.

- 주요 구획: 그라파이트 2px 선과 블루 시작점. 항목 내부: 회색 1px 선.
- 프로젝트 목업: 배경·장식 테두리·내부 라벨 없음. 원본 화면, 기기 프레임, 그림자만 사용.
- 설명 섹션: 제목 배경과 블루 좌측선, 현재 위치가 표시되는 목차.
- 모션 그래픽: AI·백엔드·앱 연결 SVG, 분야별 작은 시각 기호, 목업 hover/focus 이동.
- 반복 모션: 화면 안에서만 실행. 모션 끔·reduced-motion·인쇄는 정적 완성 상태.
- 정보 아이콘: 같은 선 굵기의 SVG와 텍스트를 함께 사용. 레이블을 아이콘으로 대체하지 않음.
- 지도는 기존 자치구 경계에 분석 입력 자료의 인구를 5구간 파란색으로 표시. 범죄 타깃·잔차는 사용하지 않음.

## 기술·도구의 표현

- 브랜드 기술 배지는 정적 정보. 클릭·선택·필터 기능을 암시하지 않음.
- 홈은 기술·도구 그룹으로 빠르게 탐색. 상세는 요구사항 → 선택 이유 → 실제 적용으로 설명.
- 기술 설명의 출처·검증 메타데이터는 내부 근거에 보존하고 공개 화면에서는 제외.

## 프로젝트 아키텍처

사용자가 제공한 Dartoo 전체 서비스 도식의 서비스 경계·방향·기여 구분을 적용.
기존 기술 목록 대신 프로젝트별 논리 구성을 SVG로 작성. 주요 서비스뿐 아니라 분석·연구·
인터랙션 구현에도 각기 다른 분기·저장·상태 구조를 표현한다.

- 역할: 블루 실선은 본인 구현·구성, 블루 점선은 연동·개선, 회색은 외부·공동 기반.
- 연결: 블루 호출·데이터 전달, 주황 작업·이벤트, 회색 저장소 접근.
- 도식이 있는 상세는 상단 가로 목차와 넓은 본문. 글자를 축소하지 않고 모바일 내부 스크롤.
- 연결 상세에 모든 구성 요소·기여 역할·방향별 연결을 텍스트로 보존.
- Dartoo: Consumer의 저장 후 요약 작업, Summary의 요약 저장, Disclosure의 이벤트 발행을 분리.
- MAP: Vision 직접 진입·BFF 동의 확인, Streams 완료 전달, 개인 초안과 영구 결과 구분.
- CareerRadar: 같은 PostgreSQL의 원본·정제·관측 영역, 내장 자료를 사용하는 탐색 웹.
- StarIndex: 공용 데이터 팩 → 앱 직접 반영과 로컬 캐시. 센서·천문 라이브러리 활용 구분.

신규 저장소의 README·핵심 코드·저장 기록을 직접 대조. 외부 라이브러리·공동 기반과
구현 범위를 구분하며 저장소의 구현을 현재 서비스 운영 성과로 확대하지 않음.

## 실행 화면과 클라우드 설명

- 웹 작업은 실제 실행 화면을 직접 캡처. 라운드 18px(모바일 12px)와 얇은 프레임만 사용.
  각 화면의 원본 비율 유지, 세로 키오스크는 최대 480px로 제한. 한 장 우선 노출과 수동 탐색.
- 색상은 정보 아이콘의 선에만 소량 추가: 서비스·클라우드 블루, 데이터·관측 틸,
  AI·연구·시험 바이올렛, 문제 해결·수상 앰버. 아이콘과 텍스트 레이블 병행.
- MAP 논리 아키텍처와 클라우드 작업 상태를 별도 섹션으로 구분.
  환경 분리·시험 배포·관측 설정을 짧은 불릿으로 표시하며 코드 구성과 구성 중 상태를 명시.
# 분석 산출물의 웹 표현

- 홈 분석 목록: 실제 서울 경계·원본 키워드의 작은 썸네일. 기존 목록 밀도 유지.
- 상세: 전처리의 입력·정제·결합·산출물 → 실제 시각화 → 필요한 수치 표 순서.
- `StudyFigure`: 흰 배경, 얇은 구분선, 제목·단위·비교 조건, native details. 넓은 연구 차트·표만 국소 스크롤 및 방향키/Home/End 지원.
- 서울 분석: 타깃·잔차 제외, 입력 변수 5×5 히트맵과 인구 지도. 분석 입력 자료의 25개 자치구 인구를 5구간으로 구분하고 인구(명)·범례·전체 수치 표·키보드 선택 제공. 현재 인구·인구밀도라는 해석 제외.
- 영화관 분석: 원본 명사 빈도 상위 20개 워드클라우드와 실제 실행 지도. 집계 정합성이 불명확한 권역 상관 그림 제외.
- 요금 정책: 누적 순보상·학습 시드 간 SD·유의차 없음의 조건부 비교.
- 빔 예측: 40시점 입력을 8개 패치로 묶는 방법 구성도. 임의 값·정확도 곡선 없음.
