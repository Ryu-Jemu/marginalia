Dartoo는 공시를 검색 가능한 데이터·요약·구독자 알림으로 연결합니다. **수집·공시·알림을 구현**하고 요약 서비스의 연동을 개선했으며, Java User 서비스의 내부 알림 API를 연결했습니다.<N id="dartoo-ownership" lang="ko" />

**원문과 데이터 계약.** Producer가 ZIP·HTML·XML을 구분하고 인코딩 후보를 적용해 UTF-8로 정리합니다. MinIO에 저장한 뒤 접수번호·객체 경로·파일 정보를 공시 워커로 전달합니다.<N id="dartoo-normaliser" lang="ko" /> 요약 태스크가 같은 객체를 읽고, 갱신된 공시의 이벤트가 알림 처리로 이어집니다.

**원문 준비와 재시도 정책.** 2026-04-08 기록에서는 영구 실패로 분류한 공시 4건이 일주일 뒤 정상 응답했습니다.<N id="dartoo-not-ready-experiment" lang="ko" /> 고정 카운터를 Redis의 재시도 시각·문서 정보로 바꾸고, 폴링 대기 중 만기 항목을 처리하도록 했습니다.

**적재와 발행의 대조.** 2026-08-13 측정 기록은 적재 959건·발행 805건으로, 차이는 154건입니다.<N id="dartoo-publisher-gap" lang="ko" /> 발행기 재연결 수정 후 기록된 단일 fixture E2E 실행에서는 적재·발행이 각각 3,948건이었습니다.<N id="dartoo-e2e-parity" lang="ko" />

**전달과 출력 품질.** 알림에는 이벤트 식별, 10단계 오케스트레이션, TTL 7일의 DLQ를 구현했습니다.<N id="dartoo-notification-scope" lang="ko" /> 구조화 페이로드를 Java User API와 맞추고, 요약에는 JSON 검증·안전 안내 응답·Redis Lua 카운터를 추가했습니다.<N id="dartoo-lua-scope" lang="ko" /> develop의 CLI로 실제 푸시 없이 외부 의존성 6종을 점검합니다.

**검증 기록.** 2026-08-13 로컬 점검에서 수집·알림·공시의 def test_ 함수 정의 319개를 집계했습니다. 실행 통과 건수가 아닌 정의 수입니다.<N id="dartoo-test-count" lang="ko" />
